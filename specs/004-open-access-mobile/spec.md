# Feature Specification: 登录即全功能可用与移动控制台重构

**Feature Branch**: `[004-open-access-mobile]`
**Created**: 2026-09-12
**Status**: Draft
**Input**: User description: "权限不用设计得这么严格，默认所有登录用户都可以访问所有页面与功能。另外移动端的功能和交互需要更改，为什么移动端的 tab 切换是在底部呢，在底部可以，但是现在底部的功能按钮太多了，这不太合适，另外移动端的功能相较于 PC 端是否有缺失也得看看，移动端的响应式和 UI 适配也得仔细看看。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登录后无角色阻断地使用控制台 (Priority: P1)

作为已登录的平台用户，我可以打开控制台的每一个页面、切换任一工作范围，并执行该页面已经提供的操作；我不会因平台角色、租户角色或尚未选定工作范围而看不到页面、被重定向、看到禁用操作或收到权限拒绝。

**Why this priority**: 用户明确要求默认所有登录用户都能使用全部页面和功能。若仍有任一入口或服务端操作保留角色门槛，体验和交付目标都会不完整。

**Independent Test**: 使用至少三种现有身份（平台管理员、普通租户成员、未选定工作范围的已登录用户）逐一访问所有控制台地址并执行每页的代表性读写操作；三者获得一致的可用页面、操作入口和结果。

**Acceptance Scenarios**:

1. **Given** 任一有效登录会话，**When** 用户直接访问控制台的概览、Agent、在线调试、任务、用量、租户、成员、Webhook、告警、审计或平台设置页面，**Then** 页面正常打开，不因用户角色而隐藏、替换、重定向或显示访问拒绝。
2. **Given** 任一有效登录会话，**When** 用户执行页面现有的创建、编辑、删除、邀请、确认、静默、测试、配置或调试操作，**Then** 操作按相同业务规则执行，不以平台角色或租户角色作为额外门槛。
3. **Given** 已登录用户尚未选定工作范围，**When** 用户打开任一页面或切换工作范围，**Then** 系统允许其进入页面并选择任一可用范围或全部范围，而不是只允许进入 Agent 目录。
4. **Given** 未登录、会话失效或已退出的访问者，**When** 访问任一受保护页面或操作，**Then** 系统仍要求重新登录，且不会泄露控制台数据或执行操作。

---

### User Story 2 - 用精简的底部导航在手机上访问全部模块 (Priority: P1)

作为手机用户，我可以保留底部导航的便利性，但底部只显示最常用的入口；其余页面、工作范围、账号和全局操作从一个清晰的“更多”入口进入，而不是在狭窄底栏中横向堆叠大量按钮。

**Why this priority**: 当前底部将全部页面平铺，标签拥挤且需要横向滚动，无法让用户一眼判断当前页面或发现次级功能。

**Independent Test**: 在手机尺寸上，从概览依次进入四个常用模块与“更多”中的每个次级页面，切换工作范围、注册 Agent 并退出登录；所有目标均可在两次或更少的导航点击内到达。

**Acceptance Scenarios**:

1. **Given** 手机纵向视图，**When** 已登录用户查看控制台，**Then** 固定底部导航恰好提供“概览、Agent、在线调试、任务、更多”五个可点击入口，且不需要横向滚动来发现它们。
2. **Given** 用户打开“更多”，**When** 查看菜单，**Then** 可进入用量、租户、成员、Webhook、告警、审计和平台设置，并可访问当前工作范围、注册 Agent、账号信息和退出登录。
3. **Given** 用户位于“更多”中的次级页面，**When** 返回控制台或再次打开“更多”，**Then** 系统清楚标示当前页面，菜单可关闭且不会遮挡正在操作的内容。
4. **Given** 用户通过深链接、浏览器前进后退或桌面链接进入任一页面，**When** 在手机上加载页面，**Then** 对应页面可正常呈现，底部或“更多”中的当前状态与页面一致。

---

### User Story 3 - 在手机上完整完成桌面工作流 (Priority: P1)

作为手机用户，我可以完成桌面控制台已有的同一套页面任务，而不必切换到电脑或依赖鼠标悬停。列表、筛选、详情、表单、确认步骤、上下文操作和错误恢复都在手机上可见、可触达且可理解。

**Why this priority**: 仅能打开页面不代表功能可用；被隐藏的侧栏、顶栏动作、表格操作或调试能力都会让移动端成为不完整的只读版本。

**Independent Test**: 按“移动端能力映射”逐项在手机上完成页面主要流程及一项次级操作，并与桌面同一账户的结果对比；不存在仅在桌面可触达的既有功能。

**Acceptance Scenarios**:

1. **Given** 用户在任一控制台页面，**When** 该页面在桌面提供导航、主要操作、筛选、排序、分页、行内操作、详情、批量操作、表单或确认步骤，**Then** 移动端为每项能力提供清晰、可触达且不依赖悬停的等效路径。
2. **Given** 用户在在线调试中使用手机，**When** 选择 Agent、管理会话、发送或停止消息、查看流式结果、处理消息操作或查看执行信息，**Then** 能完成与桌面等效的操作，并始终能返回会话与控制台。
3. **Given** 页面含有多列数据、长名称、大量筛选条件或多个并列操作，**When** 在窄屏中查看和操作，**Then** 内容以可读的响应式形式呈现；全页不发生意外的横向滚动、裁切或使关键操作不可达。
4. **Given** 某个操作正在加载、成功、失败、不可执行或需要确认，**When** 用户通过触摸或键盘与之交互，**Then** 系统提供与桌面等效的状态反馈、下一步和恢复路径。

---

### User Story 4 - 在不同屏幕与设备状态下稳定操作 (Priority: P2)

作为使用不同尺寸手机、平板或桌面的用户，我可以在旋转设备、使用安全区域、打开弹层、输入内容和浏览长列表时持续看到当前内容与关键操作，不被固定导航、键盘或浮层遮挡。

**Why this priority**: 响应式适配不仅是缩小布局；底部导航、弹层、表单、表格和流式调试区在实际设备状态下容易相互覆盖。

**Independent Test**: 在定义的手机、平板和桌面视口矩阵中，逐页执行导航、主要操作、弹层确认和错误恢复；记录溢出、遮挡、不可点击与状态不一致的问题均为零。

**Acceptance Scenarios**:

1. **Given** 320–430 像素宽的手机纵向屏幕，**When** 用户浏览任一页面、打开“更多”、填写表单或打开确认窗口，**Then** 内容、操作与关闭入口均位于可视安全区域，不被底部导航、刘海安全区、软件键盘或弹层裁切。
2. **Given** 手机横向、平板或桌面视图，**When** 用户改变屏幕方向或尺寸，**Then** 当前页面、表单数据、筛选条件和未完成操作保持一致，布局重新排布后仍可阅读和操作。
3. **Given** 触摸设备，**When** 用户使用导航、图标按钮、行操作或弹层控件，**Then** 每个可交互目标具有至少 44×44 像素的有效触摸区域，并提供明确的按下、焦点、禁用与加载反馈。

### 移动端能力映射

下表定义现有桌面能力在移动端必须保留的最小覆盖面。页面中的具体动作以交付时的能力清单为准；不得因其位于次级菜单、表格行、顶栏或侧栏而漏掉。

| 桌面区域 | 手机端必须可完成的能力 |
| --- | --- |
| 全局控制台 | 所有页面导航、工作范围切换、注册 Agent、账号查看、退出登录、深链接与浏览器前进后退 |
| 概览 | 查看运行状态和指标，并跳转到 Agent、任务和告警等关联工作流 |
| Agent 管理 | 搜索、筛选、浏览、查看详情与健康状态、注册及现有管理操作 |
| 在线调试 | 选择 Agent、创建/切换/重命名/归档/恢复/删除会话、发送/停止消息、流式结果、编辑/重新生成/分支消息、执行信息与错误恢复 |
| 任务中心 | 查询、筛选、查看任务详情、事件时间线及现有任务操作 |
| 用量分析 | 选择范围和时间条件、查看趋势与明细 |
| 租户管理 | 查看、选择和管理租户、状态及配额的现有操作 |
| 成员与角色 | 查看成员、邀请、修改、移除及现有成员操作；角色仅作信息与审计记录，不作为功能门槛 |
| Webhook | 查看、创建、编辑、测试、查看投递记录及现有订阅操作 |
| 告警中心 | 查看、筛选、确认、静默、配置规则及现有告警操作 |
| 审计中心 | 查询、筛选和查看治理操作记录 |
| 平台设置 | 查看并更新现有平台、健康检查和投递参数 |

### Edge Cases

- 已登录用户没有当前工作范围、工作范围列表为空或刚切换范围时，所有页面入口仍保持可用，并给出可恢复的空状态或选择入口。
- 页面名称、工作范围名称、账号名称或底部标签较长时，不得造成底部导航横向滚动、重叠或无法识别当前页面。
- 用户在“更多”菜单、确认窗口或在线调试抽屉打开时收到加载失败、会话断开或授权会话过期；系统必须显示明确结果、可关闭浮层且不丢失用户可安全保留的输入。
- 数据密集页面在手机上含有超长字段、超过一页的列表或大量操作时，用户仍能查看关键字段、进入详情并执行全部既有操作。
- 用户在流式调试期间切换方向、打开历史记录、使用软件键盘或返回控制台时，输入区、流式结果、停止操作和返回路径不得被遮挡或失效。
- 旧书签或直接链接指向原先仅特定角色可见的页面时，已登录用户可正常进入；未登录用户仅被引导至登录。
- 服务端或网络暂时失败时，界面不得错误地把可重试的业务失败表述为权限不足。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将“已成功登录且会话有效”作为控制台页面和功能的唯一访问前提；未登录或失效会话仍必须被阻止并引导登录。
- **FR-002**: 系统 MUST 允许每位已登录用户打开概览、Agent、在线调试、任务、用量、租户、成员、Webhook、告警、审计和平台设置全部页面，包括直接地址访问。
- **FR-003**: 系统 MUST 不再依据平台角色、租户角色或是否已选择工作范围来隐藏导航、改写页面标题、重定向页面、禁用既有操作或拒绝相同控制台操作。
- **FR-004**: 系统 MUST 允许每位已登录用户查看并切换全部可用工作范围及全部范围；工作范围用于确定当前展示和操作对象，而不是限制页面或能力。
- **FR-005**: 系统 MUST 使前端入口、深链接处理和服务端业务操作遵循同一默认开放策略，避免界面可见但实际提交被角色拒绝，或服务端可用但界面隐藏。
- **FR-006**: 系统 MUST 保留每项改变性操作的操作者、时间、对象和结果记录；角色信息可用于展示与审计，但不得作为本功能范围内的访问门槛。
- **FR-007**: 桌面端 MUST 保留完整的分组导航和全部全局入口，并对所有已登录用户显示一致的页面及操作。
- **FR-008**: 手机纵向视图 MUST 使用固定的五项底部导航：“概览、Agent、在线调试、任务、更多”；底部导航不得横向滚动，也不得直接平铺其他页面。
- **FR-009**: “更多” MUST 提供用量、租户、成员、Webhook、告警、审计和平台设置的入口，以及工作范围切换、注册 Agent、账号信息和退出登录；每项均可通过触摸与键盘操作。
- **FR-010**: 手机用户 MUST 能在一次点击到达底部四个主要页面，在不超过两次导航点击到达所有次级页面或全局操作，并能清楚识别当前页面。
- **FR-011**: 每一项桌面已有的导航、主要操作、次级操作、筛选、排序、分页、详情、行内操作、批量操作、表单、确认与错误恢复能力 MUST 在手机上存在等效、可发现且不依赖鼠标悬停的操作路径。
- **FR-012**: 在线调试 MUST 在手机上保留 Agent 选择、会话管理、流式消息、消息操作、执行信息、加载/失败反馈和返回控制台的完整闭环。
- **FR-013**: 数据密集页面 MUST 在手机上采用可读布局；关键字段、详情入口和所有既有操作不得因窄屏、长文本或数据量而裁切、重叠或不可达。
- **FR-014**: 页面级弹层、抽屉、菜单、确认提示、输入区和加载状态 MUST 在手机上正确叠放并响应安全区域、软件键盘和底部导航，始终保留关闭、返回或继续操作的路径。
- **FR-015**: 在 320–430 像素宽手机纵向、常见手机横向、平板纵向和桌面视图中，系统 MUST 避免全页意外横向滚动、内容裁切、重叠、无法点击的控件与被固定元素遮挡的内容。
- **FR-016**: 触摸设备上的每个交互控件 MUST 提供至少 44×44 像素的有效触摸区域；触摸不依赖悬停，并具有默认、按下、焦点、禁用、加载、成功和失败状态中适用的可感知反馈。
- **FR-017**: 键盘和辅助技术用户 MUST 能识别导航、当前页面、菜单展开状态、操作名称与状态变化，并能完成与触摸用户相同的页面和功能访问。
- **FR-018**: 交付时 MUST 提供覆盖“移动端能力映射”中所有区域的桌面/移动验证记录；每项记录应说明入口、完成动作、结果和异常状态验证。

### Key Entities *(include if feature involves data)*

- **已登录用户**: 已通过现有身份验证并持有有效会话的控制台用户；本功能中不因角色不同而获得不同的控制台能力。
- **工作范围**: 用户当前查看和操作的数据范围，可为单个租户或全部范围；它决定内容上下文，不决定能否进入页面或使用功能。
- **控制台能力**: 一个用户可完成的页面入口、查看、筛选、编辑、提交、确认、调试、恢复或全局操作。
- **主要导航项**: 手机底部直接显示的概览、Agent、在线调试和任务入口。
- **更多菜单**: 手机承载次级页面和全局操作的统一入口，避免底部导航堆叠。
- **操作审计记录**: 对改变性操作的操作者、时间、对象、结果与工作范围的可追踪记录。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用至少三种现有登录身份对全部 11 个控制台页面进行直接访问测试时，100% 页面可打开，且不存在由角色或未选工作范围导致的隐藏、重定向、禁用或访问拒绝。
- **SC-002**: 对每个页面各抽取至少一项查看操作和一项改变性或上下文操作进行验证时，所有已登录身份的成功率为 100%，业务失败不会被误报为权限失败。
- **SC-003**: 在 320、360、390 和 430 像素宽的手机纵向视图中，100% 底部导航可一次性完整显示五项入口且不产生横向滚动；全部次级页面和全局操作均可在两次或更少的导航点击内到达。
- **SC-004**: 对“移动端能力映射”列出的每个区域逐项完成验证时，100% 桌面既有能力在手机上拥有可发现、可触达且不依赖悬停的等效路径。
- **SC-005**: 在手机纵向、手机横向、平板纵向和桌面四类视图中执行导航、表单、确认窗口、长列表和错误恢复检查时，零项出现全页意外横向滚动、关键内容被固定元素遮挡、控件不可点击或缺少关闭/返回路径。
- **SC-006**: 对触摸可操作控件抽样检查时，100% 符合至少 44×44 像素有效触摸区域要求，并在适用的按下、焦点、禁用、加载、成功和失败状态中提供可感知反馈。
- **SC-007**: 在手机上完成一轮在线调试会话管理、流式交互、消息操作与返回控制台验证时，100% 流程可完成且不会因打开历史记录、键盘或方向变化失去输入、停止或返回路径。

## Assumptions

- 本控制台面向已获平台登录资格的内部用户；本规格开放的是登录后的控制台访问，不会把页面或接口公开给未登录访问者。
- 既有角色、成员和工作范围数据继续保留，用于显示、筛选和操作审计；本功能不要求删除这些数据模型或身份登录流程。
- “所有页面与功能”覆盖本规格中列出的 11 个现有控制台页面，以及它们交付时已存在的全局、主要、次级和上下文操作；新增业务模块不在本次范围内。
- 桌面端继续使用完整侧栏导航；移动端以五项底部导航和“更多”菜单承载同一信息架构。
- 当业务对象不存在、输入不合法、网络故障或服务不可用时，系统仍可显示相应业务错误和恢复措施；这类反馈不属于角色权限限制。
- 移动端验证覆盖真实触摸交互和主流手机/平板视口；不以静态截图代替操作验证。

## Out of Scope

- 更换现有身份提供方、登录方式或会话生命周期。
- 删除角色、成员、租户或审计数据模型。
- 添加本规格列出页面之外的新业务模块。
