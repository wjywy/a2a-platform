# Research: 登录即全功能可用与移动控制台重构

## Decision 1: 以认证状态替代角色门槛，而非只隐藏前端元素

**Decision**: 所有控制台路由和既有操作以有效登录会话为访问条件。角色字段继续存在于身份、成员和审计记录中，但不再用于控制台 API 的拒绝、页面重定向、导航过滤或按钮禁用。仍保留账户禁用检查、请求中目标范围的完整性验证、资源存在性验证、服务凭据与目标范围一致性验证，以及审计记录。

**Rationale**: 当前限制分布在浏览器壳层、页面组件、认证帮助函数和路由内的手工条件中；只解除 UI 限制会产生“看得见却提交失败”，只改 API 又会留下不可发现的功能。

**Alternatives considered**:
- 仅将前端写入/管理标记置为真：拒绝，因为现有 API 仍会返回角色错误。
- 仅将 API 的角色中间件改为空：拒绝，因为导航、标题和页面操作仍会缺失。
- 删除角色和成员数据：拒绝，因为用户仅要求放宽访问，且角色/成员仍是运营信息和审计事实。

## Decision 2: 每位登录用户可使用全局工作范围

**Decision**: 控制台范围选择始终加载所有可用租户及“全部范围”，不再按用户的成员角色回退为公开目录或单一租户。范围决定读取和写入对象的上下文，不决定页面可见性。针对范围的 API 仍要求请求提供可识别的目标；未选择范围时 UI 显示可恢复的选择状态而非重定向。

**Rationale**: 这是“所有登录用户都可以访问所有页面与功能”的必要条件，也可消除当前 API 和控制台对于平台管理员、普通成员的分支。

## Decision 3: 手机使用五项固定底栏与“更多”面板

**Decision**: 手机底栏固定为概览、Agent、在线调试、任务、更多五项。更多面板承载用量、租户、成员、Webhook、告警、审计、平台设置，以及范围切换、注册 Agent、账号和退出登录。次级页面激活时，更多入口显示当前次级导航状态；面板支持点击外部、显式关闭、键盘关闭和焦点返回。

**Rationale**: 当前将 11 个页面横向排列在底栏，造成标签拥挤和隐性横向滚动。五项结构保留高频操作的单击路径，低频治理页面仍在两步内可达。

## Decision 4: 用壳层安全区统一协调常规页面和在线调试

**Decision**: 壳层提供统一的移动底部安全区变量。常规页面、更多面板、抽屉和确认窗口据此避开系统安全区和底栏。在线调试仍保留其聊天工作区，但移动端在全局导航可见时为输入区、历史抽屉和流式结果预留相同的底部空间；返回控制台继续可用。

**Rationale**: 在线调试的输入区是高频控制，若与固定导航重叠，发送、停止和错误恢复会不可达。

## Decision 5: 以实际功能路径验证移动端等效性

**Decision**: API 测试验证非管理员登录会话可完成代表性受保护操作；Playwright 覆盖全部 11 个页面的直接访问、五项导航、更多菜单、范围/账号入口、无横向页面溢出和在线调试手机关键路径。桌面回归保持完整侧栏和深链接行为。

**Rationale**: 静态样式检查无法证明隐藏操作、服务端守卫或流式工作区在手机上真正可用。
