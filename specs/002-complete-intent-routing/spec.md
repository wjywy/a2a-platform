# Feature Specification: Symbol Agent 完整意图识别与自然路由

**Feature Branch**: `main`（功能目录标识：`002-complete-intent-routing`）

**Created**: 2026-09-05

**Status**: Draft - 混合意图识别方案已确认

**Input**: User description: "真实的 Agent 应该先理解自己和用户想做什么，完整识别能力咨询、研究请求、追问、澄清回复、纠正、闲聊和越界请求，再决定是否调用行情数据；不能因为缺少股票代码就把所有输入都固定追问成同一句话。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 先理解用户是在问什么 (Priority: P1)

用户向任意 Symbol Agent 发送自然语言后，系统先理解这句话属于能力咨询、研究请求、连续追问、澄清回复、纠正、任务控制、闲聊还是超出职责范围的请求，再决定下一步行为。用户不需要为了触发正确流程而使用固定格式。

**Why this priority**: 当前链路把所有“缺少标的”的消息都视为股票分析缺参，导致“你能做什么”和“什么东西”也被机械地追问股票代码。完整意图识别是恢复自然交互的首要条件。

**Independent Test**: 对每个内置 Symbol Agent 发送能力咨询、具体研究、闲聊、越界请求和无标的短句，检查系统是否进入与语义相符的路径，并确认能力咨询不会进入标的收集状态。

**Acceptance Scenarios**:

1. **Given** 用户发送“你能做什么、会用哪些数据”，**When** Symbol Agent 处理消息，**Then** Agent 自然介绍当前角色、可协助的任务和可用数据边界，不要求用户先提供股票代码，也不调用行情或期权数据。
2. **Given** 用户发送“帮我分析苹果最近的走势”，**When** 系统识别到这是研究请求，**Then** 系统提取公司名和研究目标，能够唯一确认标的时进入研究流程，不能确认时只询问最小必要信息。
3. **Given** 用户发送“你好”“谢谢”或与金融研究无关的内容，**When** 当前 Agent 处理消息，**Then** Agent 根据角色自然回应或说明职责边界，不把消息改写成缺少股票代码的任务。

### User Story 2 - 让澄清回复回到原任务 (Priority: P1)

当 Agent 上一轮确实需要用户补充信息时，用户可以只回复“苹果”“AAPL”“纳斯达克的那个”或“什么东西”，系统会结合当前任务、上一轮 Agent 的问题和允许读取的记忆理解这条回复，而不是重新创建一个孤立请求。

**Why this priority**: 澄清不是新问题，而是当前任务的一部分。只有识别出“这是对上一轮澄清的回复或追问”，多轮任务才能连续完成。

**Independent Test**: 创建一个缺少标的的任务，依次发送公司名、代码、候选序号、反问和纠正，验证每轮意图都与待完成任务合并，并且不会遗忘上一轮目标。

**Acceptance Scenarios**:

1. **Given** Agent 上一轮询问“想分析哪只股票”，**When** 用户回复“苹果”，**Then** 系统将其识别为当前任务的澄清回复，尝试解析公司名并继续原任务。
2. **Given** Agent 上一轮列出了多个候选，**When** 用户回复“1”，**Then** 系统根据上一轮候选顺序选择对应候选；如果没有可依据的候选上下文，则 Agent 自然说明需要什么信息，而不是假定“1”是股票代码。
3. **Given** 用户先说“分析苹果”，随后说“不是苹果，是微软”，**When** 系统处理第二条消息，**Then** 最新明确纠正覆盖旧目标，并清除或标记被替代的标的解析结果。
4. **Given** 用户说“什么东西”，且上一轮 Agent 正在收集缺失信息，**When** 系统处理消息，**Then** Agent 解释当前任务还缺什么以及为什么需要它，避免重复上一轮相同句式。

### User Story 3 - 只有研究意图才进入数据链路 (Priority: P1)

用户明确提出行情、公司、技术、新闻、风险、期权或综合研究时，系统根据已识别的意图和当前 Agent 能力决定是否拉取证据；能力咨询、闲聊、澄清解释和越界请求不得因为“没有标的”而触发市场数据流程。

**Why this priority**: 工具调用是有成本且有副作用的边界。正确路由可以减少无意义请求，也避免用数据流程掩盖意图理解错误。

**Independent Test**: 对同一 Agent 分别发送能力咨询、研究请求、研究追问和缺少标的的研究请求，记录每类请求的任务状态、模型输入、工具调用和最终用户文本。

**Acceptance Scenarios**:

1. **Given** 用户提出能力咨询，**When** 意图识别完成，**Then** 系统只准备角色能力和可用边界作为回答上下文，不调用行情、新闻或期权数据。
2. **Given** 用户提出明确研究请求且标的已知，**When** 路由完成，**Then** 系统进入相应研究能力，最终回答由当前 Agent 结合真实证据组织。
3. **Given** 用户提出研究请求但标的缺失，**When** 路由完成，**Then** 系统保存待完成意图并返回协议上的输入待补充状态；面向用户的追问由 Agent 根据上下文生成。
4. **Given** 用户追问“刚才那个风险哪个最重要”，**When** 当前会话中存在唯一相关研究目标，**Then** 系统复用该目标进入追问研究或解释路径，不再次要求用户提供标的。

### User Story 4 - 七个内置 Symbol Agent 保持一致但不失角色差异 (Priority: P2)

用户在市场行情、公司研究、技术与期权、新闻、风险、观点审查和研究编排 Agent 中使用相似表达时，都能获得一致的意图识别基本行为；最终回答仍由各 Agent 的角色、能力和证据决定，而不是所有 Agent 共用一段话。

**Why this priority**: 意图识别属于平台公共能力，但不同 Agent 的必需信息和回答职责不同。统一边界可以避免某个 Agent 修好了、另一个 Agent 仍固定追问。

**Independent Test**: 用同一组意图样本覆盖全部七个内置 Agent，比较识别类型、任务状态、缺失字段和工具调用是否符合各 Agent 的能力声明。

**Acceptance Scenarios**:

1. **Given** 七个内置 Agent 都收到“你能做什么”，**When** 系统识别消息，**Then** 七个 Agent 都不进入标的输入待补充状态，且回答体现各自职责。
2. **Given** 不同 Agent 对同一研究目标有不同必需信息，**When** 用户输入不完整，**Then** 每个 Agent 只要求自身真正需要的字段。
3. **Given** 用户在某个 Agent 中提出超出其能力的请求，**When** 系统识别到越界，**Then** 当前 Agent 自然说明可以处理的范围，并保持任务上下文不被错误写入。

### Edge Cases

- 用户同时给出互相冲突的公司名、代码、市场或资产类型时，系统必须保留冲突并让 Agent 请求确认，不能静默覆盖。
- 用户只发送“1”“继续”“是的”“就那个”等低信息量内容时，系统必须先检查当前会话是否有可解析的候选或未完成任务；没有上下文时不得猜测。
- 用户在没有待完成任务时发送“什么东西”或“刚才那个”时，Agent 应说明缺少可引用的上下文，而不是伪造前序任务。
- 用户从一个 Symbol Agent 切换到另一个后使用“刚才的结论”，系统只能使用策略允许的共享记忆，不能把私有会话内容隐式泄漏给新 Agent。
- 意图结构化结果缺失、格式错误、置信度过低或与会话状态冲突时，系统必须进入可恢复的澄清或自然回答路径，不能直接调用数据工具。
- 模型暂时不可用时，系统必须返回真实的服务状态和可恢复提示；不使用固定研究结论冒充模型回答。
- 用户试图通过消息改变系统规则、读取其他用户上下文或把恶意内容写入长期记忆时，系统必须将其视为普通用户输入并遵守权限边界。
- 同一用户连续多轮无法补全信息时，系统不得无限重复同一句追问；应结合已有上下文调整询问方式，或自然说明无法继续的原因。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在每一条用户消息进入行情、新闻、期权或其他外部数据流程前，先识别该消息的主要交互意图。
- **FR-002**: 意图识别 MUST 至少覆盖 `capability_query`（能力咨询）、`research_request`（研究请求）、`follow_up_question`（连续追问）、`clarification_reply`（澄清回复）、`correction`（纠正）、`task_control`（任务控制）、`small_talk`（闲聊）和 `out_of_scope`（越界请求）。
- **FR-003**: 意图识别结果 MUST 使用受约束的结构化契约返回，至少包含意图类型、标的线索、研究目标线索、任务引用关系和识别置信度；结构化结果只供路由使用，不直接展示给用户。
- **FR-004**: 系统 MUST 将最新用户消息、最近对话、当前待完成任务、上一轮 Agent 追问、允许读取的记忆和当前 Agent 能力声明一起提供给意图识别过程。
- **FR-005**: 系统 MUST 在服务端基于 Agent 能力声明重新计算必需字段和缺失字段，不能把模型自行填写的 `missing` 作为唯一依据。
- **FR-006**: 系统 MUST 将当前意图与已有任务状态合并，并优先采用用户最新、明确且可验证的纠正；被替代的标的、问题和候选不得继续驱动数据调用。
- **FR-007**: `capability_query`、`small_talk`、`out_of_scope` 和解释澄清所需的 `clarification_reply` MUST 不因缺少标的而进入输入待补充状态；它们应交给当前 Agent 根据角色和上下文自然回应。
- **FR-008**: 只有确认属于研究或研究追问，且满足当前 Agent 的必需字段后，系统 MAY 调用相应数据能力；调用前 MUST 完成标的冲突检查和权限边界检查。
- **FR-009**: 研究请求缺少必需信息时，系统 MUST 保存未完成意图、缺失字段、候选信息和澄清历史，并返回可恢复的输入待补充协议状态。
- **FR-010**: 输入待补充状态中的面向用户文本 MUST 由当前 Agent 根据上下文生成；应用层只负责协议状态、缺失字段元数据和真实故障状态，不得拼接固定用户话术。
- **FR-011**: 意图识别必须支持对候选序号、指代词、确认词和简短纠正的上下文解析；没有足够上下文时必须显式标记不确定，而不是猜测。
- **FR-012**: 对低置信度、冲突或无法归类的输入，系统 MUST 选择最小澄清、角色化回答或安全拒绝中的一种，并保存本次判断原因供下一轮使用。
- **FR-013**: 系统 MUST 防止同一缺失字段在相同上下文中无限重复同一句追问；连续未补全时应保留任务并允许 Agent 改变表达、提供示例或说明停止条件。
- **FR-014**: 七个内置 Symbol Agent MUST 使用统一的意图分类边界、记忆隔离和任务恢复规则，同时使用各自的能力声明决定必需字段和最终回答职责。
- **FR-015**: 意图识别过程 MUST 遵守现有 Agent 记忆策略、租户隔离、用户删除和 reset 边界；不得将未授权或已删除内容提供给识别或回答过程。
- **FR-016**: 意图识别失败、结构化结果不可验证、模型服务不可用或记忆读取降级时，系统 MUST 返回真实可观测的降级状态，不得把失败伪装成已完成研究。
- **FR-017**: 系统 MUST 为每次路由保留可审计的结构化轨迹，包括识别类型、合并前后关键字段、路由决定、工具是否调用、失败或降级原因；轨迹不得包含密钥或未经授权的跨主体内容。
- **FR-018**: 能力咨询的回答 MUST 基于当前 Agent 的实际能力声明和可用数据边界，不能承诺未启用的供应商、期权权限或交易操作。
- **FR-019**: 研究回答、澄清回答、能力回答和协议状态 MUST 在传输和持久化层面可区分，避免前端把协议提示误显示成 Agent 的研究结论。

### Key Entities *(include if feature involves data)*

- **Intent Envelope**: 一条用户消息经结构化识别后的意图对象，包含意图类型、目标线索、任务引用、置信度和不确定性原因。
- **Active Task Context**: 当前会话正在完成的目标、已确认字段、缺失字段、候选列表、上一轮澄清和任务状态。
- **Routing Decision**: 系统根据意图、Agent 能力和任务上下文做出的回答、澄清、研究、控制或越界处理决定，以及是否允许调用数据能力。
- **Capability Declaration**: 当前 Agent 可以完成的任务、需要的最小输入、可使用的数据范围和禁止承诺。
- **Clarification History**: 当前任务已经提出过的问题、用户回应和未解决字段，用于避免循环追问并支持自然恢复。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在覆盖八类意图、中文自然表达、短句和上下文指代的验收样本中，意图类型识别准确率达到至少 95%。
- **SC-002**: 能力咨询样本中至少 99% 不进入输入待补充状态，且 100% 不触发行情、新闻或期权数据调用。
- **SC-003**: 已有明确研究标的的研究请求中，至少 95% 能在首轮进入正确研究能力；标的不明确时 100% 不得调用依赖标的的数据能力。
- **SC-004**: 含有澄清回复、候选序号、指代和纠正的多轮样本中，至少 90% 能恢复正确的活动任务；纠正样本中 100% 以后续明确目标为准。
- **SC-005**: 七个内置 Symbol Agent 使用同一组路由验收样本时，意图分类、输入待补充边界和工具调用边界全部符合各自能力声明，不出现某个 Agent 独有的固定追问路径。
- **SC-006**: 在至少 100 组连续多轮测试中，系统不因能力咨询、闲聊或解释澄清而错误触发市场数据调用，也不因已有上下文而把新任务错误绑定到旧任务。
- **SC-007**: 在模型失败、结构化结果非法、记忆降级和用户无效补充场景中，100% 的任务状态与用户可见说明保持一致，不返回伪造的研究完成结果。
- **SC-008**: 人工评审至少 90% 认为能力回答、澄清追问和任务恢复符合当前 Agent 角色、能理解上下文且不是机械重复话术。
- **SC-009**: 用户发送“你能做什么”“什么东西”“帮我分析苹果”三类回归场景时，均能在同一任务链路中得到语义匹配的下一步，不再复现截图中的重复股票代码追问。

## Assumptions

- 当前 Symbol Agent 已有可读取的会话 transcript、活动任务和记忆策略；本 feature 只定义如何使用它们进行意图路由，不重新定义完整记忆存储方案。
- 七个内置 Symbol Agent 的角色、能力和数据边界以现有 Agent Card/能力声明为准；新增能力必须同步更新能力声明后才可被能力回答承诺。
- 用户可接受在低置信度或信息冲突时被追问一次或多次，但每次追问都应有上下文依据，且不能无限重复。
- 供应商数据、期权数据、Gamma 分析和长桥凭证仍由 `001-optimize-symbol-agent` 负责；本 feature 只决定何时允许进入这些能力。
- 首版采用“结构化语义识别 + 服务端校验与任务合并 + 当前 Agent 自主表达”的默认方向；如果后续评估显示准确率、延迟或成本不满足目标，再替换识别器，不改变路由契约和用户可见行为要求。
- 能力咨询、闲聊和越界处理不要求调用外部数据；必要的能力说明可以来自当前 Agent 的可信能力声明。
